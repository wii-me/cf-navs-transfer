# App.svelte 拆分计划

> 代码审查三轮第 7 项起步。`src/App.svelte` 是全站控制器：拆分前 1415 行（`<script>` 约 1155 行，模板约 260 行，无 `<style>`）。
> 每一步都应**独立可发布**：无行为变化、补纯逻辑单测、`lint` / `type-check` / `test` / `build` / `smoke` 全绿、首屏 `index-*.js` 不增大。

## 现状

- 依赖 `svelte@^5.57`，`svelte.config.js` 未开启 `runes`，App 及组件仍用 `$:` / `export let` / `on:`，即 **Svelte 5 的 legacy（兼容）模式**。第 8b 步起 App.svelte 单文件开启 runes（`<svelte:options runes />`），第 8c 步起 14 个层级 0 纯展示组件、第 8d 步起 9 个层级 0 有状态组件、第 8e 步起 6 个 ui / 事件分发叶子、第 8f 步起 Install / Recover 两个视图、第 8g 步起 11 个层级 1 首页 / 书签组件、第 8h 步起 admin 三个面板与七个设置分区、第 8i 步起层级 2 的 6 个组件与 Toast、第 8j 步起 6 个顶层组件也已逐文件开启：**`src/` 下已无 legacy 组件**（全局 `runes` 编译选项有意不开，见第 8 步完成记录）。
- 已有一批纯逻辑模块（`appAuthController`、`appInstall`、`appNavigation`、`appThemeState`、`appConfirmDialog`、`appModalState`、`appSortQueue`、`appImportExport`、`appLazyComponent`、`appData`、`dataService` 等），App 剩下的主要是「状态变量 + 用例编排 + 模板接线」。
